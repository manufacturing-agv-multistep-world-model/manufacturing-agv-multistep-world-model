# V12 充电感知物理图世界模型修复说明

## 为什么 V11 四小时试验没有通过

V11 会提出返回充电站的候选动作，但原门槛要求该动作在三步预测内立即降低能耗。提前充电本身会先增加行驶和充电成本，因此这个条件与物理过程不一致。更重要的是，旧训练数据由大量 400 至 500 步的短回合组成，车辆尚未进入集中充电阶段就被重置，训练集中没有充电排队事件。因而不能把 V11 的零次充电授权解释为世界模型有效或无效。

## V12 的结构性修复

1. 保留 V11 的物理边特征、局部车辆状态、离散节点预测和多步状态滚动。
2. 新增两个独立监督输出：路线阻塞车辆步数、充电排队车辆步数。
3. 采用 4000 步连续物理轨迹，使电池放电、返回充电和充电排队完整发生。
4. 训练集与验证集按完整回合划分，并强制两侧都包含充电排队事件，避免相邻转移泄漏。
5. 对含充电排队事件的序列使用数据驱动的稀有事件采样权重，目标占比为 25%，权重上限为 25。
6. 当充电容量小于车队规模时，禁止把“全车同时主动充电”作为候选动作；强制低电量保护仍由解析安全基线执行。

## 主动充电授权条件

只有同时满足以下条件，世界模型才能覆盖解析基线：

1. 仅有一辆空载车辆被新增为主动充电动作。
2. 该车电量高于强制充电阈值、但不高于阈值加 8 个百分点，保证动作确实是提前充电而非低电量强制保护。
3. 当前和已在途车辆没有占满充电能力。
4. 接近充电阈值的车辆数大于充电位容量，存在可解释的未来集中充电压力。
5. V12 专用输出预测累计充电排队至少减少 0.5 个车辆步。
6. 预测产出不低于解析基线，且即时物理检查不增加阻塞或冲突。

## 开发验证结果

- 自动测试：41 项全部通过。
- 长轨迹烟雾数据：16000 个转移，包含 13661 个路线阻塞监督步和 124 个充电排队监督步。
- 训练集充电事件序列：30/1200；数据驱动采样权重为 13.00。
- 一轮烟雾训练和开放环诊断均能完整运行。

这些烟雾结果只证明代码链路和监督可识别性，不属于论文正式结果。

## 正式执行顺序

1. 在显卡电脑运行 `scripts/93_train_charge_aware_world_model_v12_seeds.ps1 -RequireGpu`。
2. 将三个 `world_model_runs/pi_gwm_multistep_v12_charge_seed*` 文件夹和共享缓存复制回主项目。
3. 运行 `scripts/94_diagnose_charge_aware_world_model_v12.ps1`，先检验专用充电排队输出，再决定是否进入控制试验。
4. 只有三套独立模型中至少两套通过开放环诊断，才运行一小时和四小时决策试验。
