# N1 开发实验 V3 失败审计

## 结论

`n1_decision_attribution_development_v3_ensemble` 不能用于论文性能结论，也不能进入冻结确认实验。该结果只保留为开发审计证据。

## 发现的问题

1. 同一环境随机种子下，四种方法收到的外部订单流不一致。比较因此不再满足配对实验的公平性要求。
2. `DT-aware` 在环境种子 31003、`Data-only graph MPC` 在环境种子 31004 没有完成任务，导致单位任务能耗为非有限值 `nan`。
3. 旧分析器仅检查了平均控制计算时间，没有把零产出和非有限能耗作为硬失败条件，因而部分性能门槛被错误显示为通过。

## 根因

泊松订单的所有任务模板共用了一个随机数生成器。不同控制策略产生不同的物理步长和事件批次后，下一次随机抽样会被分配给不同任务模板。因此，策略动作间接改变了未来外部订单流。

## 修正措施

1. 每个任务模板使用由同一环境种子派生的独立随机数流。
2. 配对方法继续使用相同环境种子，并以共享物理时间截止点计算订单流哈希。
3. 将训练轨迹缓存协议升级为 `assignment_visible_congestion_independent_arrival_streams_v4`，旧缓存禁止复用。
4. 分析器新增两项硬门槛：每个方法每次运行至少完成一个任务；所有报告的单位任务能耗必须为有限值。
5. 增加三个环境种子、1800 秒截止时间、两类明显不同动作策略的任务流一致性自动测试。

## 对既有证据的影响

- N1 V3 的控制性能数字全部作废，只保留故障发现与协议改进记录。
- 旧 V11 预测消融使用共同的留出轨迹，原有配对统计本身没有因策略间订单不一致而直接失配；但是训练轨迹来自旧环境。为形成可投 Journal of Manufacturing Systems 的统一证据链，四个 V11 条件必须在修正后的环境上重新训练与复核。
- AnyLogic 独立验证和历史系统趋势结果不因此自动作废，但不能代替新 V11 的重新训练和公平闭环比较。

## 后续放行顺序

1. 自动测试全部通过。
2. 使用新缓存和新目录重新训练 V11 四个物理因子条件、三个模型种子。
3. 重新执行留出预测消融，确认世界模型本身的多步预测证据。
4. 仅在预测证据通过后，重新执行 N1 开发实验。
5. N1 开发实验全部硬门槛通过后，才允许冻结确认设计。
