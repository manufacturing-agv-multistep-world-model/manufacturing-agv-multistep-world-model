# V14.7b-R1 死锁恢复期间任务到达修复说明

## 发现的问题

旧环境在每个正常决策步结束时释放外生任务。如果该步随后触发死锁恢复，恢复过程会继续消耗物理时间，但恢复期间到达的任务要到下一决策步结束后才被登记。当固定时长实验恰好在恢复后结束时，这些任务不会进入终点任务流签名。

种子 16002 的旧四小时开发结果因此出现配对任务数 370 对 368。独立重建同一种子的四小时泊松任务流得到 370 个任务，并与基线签名完全一致。

## 修复内容

- 死锁恢复结束后立即再次释放恢复期间到达的任务。
- 新任务在下一次动作选择前进入可观察状态并按原有规则分配。
- 不修改世界模型参数、模型结构、预测时长、效用权重、门槛或安全约束。
- 保留旧结果目录，不覆盖、不删除，作为实现审计记录。

## 重跑规则

修正版命名为 V14.7b-R1，仍使用开发种子 16001-16005、四小时物理时长、720 秒干预隔离和每次最多 8 次接管。重跑只用于验证实现修复后的协议完整性，不能把同一批种子用于继续调参。

只有全部预注册标准通过，才可另行设计未见种子的正式确认实验。
